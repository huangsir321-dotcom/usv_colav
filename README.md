# 无人艇自动避碰仿真 + 强化学习工程（1V1 / 1V2 / 1V3）

本工程提供 Windows 桌面仿真界面、透明规则基线、基于 Gymnasium + Stable-Baselines3 PPO 的训练入口、CPA/TCPA、会遇态势、风险近似等级、CSV 运行记录和 PPO 动作安全筛查层。船舶运动从简单点质量更新加强为“航向变化率受限 + 转向角速度变化受限 + 纵向加减速受限”的简化 3-DOF-lite 模型；目标船默认按输入航向/航速保向保速，本船沿计划航线航行，可转向及减速避让。

> **重要限制：** 这是研究/教学仿真原型，不是经 CCS/船级社认可的系统，不是经过实船验证的自动驾驶控制软件。风险等级为工程内近似实现，不能等同于 GB/T 46851 附录 A 所有临界距离公式。PPO 输出必须经过场景测试、安全评审、船舶操纵模型标定和硬件在环测试后，才可讨论与真实无人艇的集成。请勿将训练策略直接接到实船舵机/推进器。

## 2. Windows 11 启动界面

1. 安装 Python 3.10 或 3.11（安装界面勾选 **Add Python to PATH**，并确保安装 Tk/Tcl 组件）。
2. 解压 ZIP，进入 `usv_colav_ccs_rl` 文件夹。
3. 双击 `run_gui.bat`；或者打开命令提示符，执行：

```bat
python run_gui.py
```

GUI 初始选择为“对遇测试 + 1V1 + 规则基线”。选择预设后，可以修改本船航速/航向、默认 SDA、仿真步长与每艘目标船的航速/航向/距离/相对方位；目标船 SDA 列可选填，空白时继承本船的默认 SDA。相对方位以本船艏向为 0°，右舷为正、左舷为负。点击“重置场景”应用参数，“单步运行”逐帧计算，“开始运行”连续仿真。

每次重置会在 `logs/` 新建 CSV 文件，包含每步本船状态、动作、距离、每艘目标的 CPA/TCPA、会遇类别、风险标签、位置快照、SDA 违规、传感器可见目标数、故障模式、环境参数与障碍物净空。点击“停止 / 保存日志”会关闭当前日志文件。


## 3. 运动学与 COLREGs 安全层

- **转向动力学**：本船不再在每一步直接跳到目标航向；使用受限航向角速度、角速度变化率及纵向加减速，模拟转向惯性。可在 `SimConfig` 中调整 `max_turn_rate_deg_s`、`max_yaw_accel_deg_s2`、`max_accel_kn_s`。
- **PPO 动作筛查**：强化学习动作先经过 `usv_colav/safety_filter.py`。对原动作做 90 秒离散预测；若最小预测间距没有留出安全缓冲，则对多个航向偏置和速度比例进行多目标联合前向评估，优先选择安全余量更大且操纵代价较低的动作。无候选动作满足缓冲时会给出明确警告文本，应停止自动运行并由人评估。
- **COLREGs 启发式**：对遇场景和本船为让路船的右舷交叉场景优先考虑及早向右改向；本船处于直航船且风险尚不紧迫时偏好保向保速。多目标之间发生规则冲突时，筛查器仍以全目标的预测间距为主，不保证能在所有几何条件下找到完全符合规则的动作。
- **明确限制**：这不是形式化安全证明，也不是完整 COLREGs 法律推理器。转向模型是研究用简化近似，必须用实际无人艇操纵性试验数据标定。

## 4. 本次新增：传感器误差、环境扰动、障碍物与系统失效

`SimConfig` 已增加可配置的传感器参数：位置测量标准差（m）、航向误差（°）、航速误差（kn）、随机丢检概率与可见距离。控制器和安全筛查层读取带噪声的传感器快照；真值仍用于碰撞/SDA 结果统计。目标超出能见/探测距离时会从当前控制观测中消失，观测维度仍保持兼容既有的 37 维 PPO 接口。

环境扰动采用明确的简化模型：洋流按设定流向对所有船施加漂移；风按经验系数形成小幅漂移；波浪以周期横向漂移和航向扰动近似。它们不是经过船型参数标定的风浪流动力学模型，参数仅供鲁棒性实验使用。

静态障碍物使用圆形障碍表示，输入为局部 East/North 坐标及半径。GUI 的“环境扰动 / 系统失效注入”菜单可选正常、风浪流、受限能见度、强传感器噪声、GNSS 失效、罗经偏差、推进失效、舵机卡滞、传感器掉线或静态障碍物；“故障触发步数”控制故障启动时间。地图会绘出障碍物，CSV 增加故障状态、可见目标数、环境参数和障碍净空记录。

支持的故障注入包括：

- `gnss_loss`：GNSS 位置观测冻结为最近一次有效值；
- `compass_bias`：罗经观测叠加固定偏差；
- `propulsion_loss`：推进速度按加速度限制衰减至零；
- `rudder_jam`：舵向响应失效；
- `sensor_dropout`：目标传感器观测掉线。

关键传感器/操纵故障或当前没有任何目标回波时，动作安全层请求停推进并提示人工接管。由于惯性、洋流、操纵器故障和探测盲区仍存在，这个“停推进请求”并不保证船会立即停止或必然避碰；压力测试中的未完成/失败结果会保留，不把达到最大步数当作安全通过。

运行完整鲁棒性矩阵（默认每个工况跑 2 个回合）：

```bat
python stress_test.py --episodes-per-case 2 --max-steps 120
```

结果写入 `results/robustness_stress_test.csv`。工况包括名义环境、传感器噪声、风浪流、受限能见度、静态障碍物、GNSS 失效、罗经偏差、推进失效、舵机卡滞和传感器掉线。可以增加每种工况回合数，例如 `--episodes-per-case 30`，用于更有统计意义的回归。

PPO 训练默认开启环境随机化：每个回合随机改变传感器误差、可见距离、风浪流、偶发失效和障碍物。想做名义环境对照实验时使用 `--no-domain-randomization`。环境随机化不会自动证明策略鲁棒，训练后仍需独立压力测试。

```bat

```

> PPO 需要大量场景随机化和评估，短时间训练通常不能证明策略有效。请先对规则基线做回归，再比较 PPO 的安全通过率、SDA 违规次数、最小分离距离和碰撞次数，不要只看累计奖励。

## 8. CPA/TCPA 的定义与输入字段

每艘目标船至少需要：相对位置/距离、相对方位（或绝对经纬度）、航向 COG、航速 SOG、船长/尺度、目标类型；本船需要自己的位置、航向、航速与原计划航线。真实系统还需要时间戳/感知延迟、船舶操纵响应（转向率/旋回圈/进距/停船距离）、安全会遇距离 SDA、环境/水域/能见度、静态障碍物与设计运行范围信息。

工程采用局部平面 East-North 坐标；航向 0°=北、90°=东、顺时针增大。相对速度为目标船速度矢量减本船速度矢量：

- `TCPA = - (r · v_rel) / |v_rel|²`，单位分钟；正值表示最近会遇点在未来，负值表示线性相对运动下已过最近点。
- `CPA = |r + v_rel * TCPA_seconds|`，单位米；相对速度接近零时，TCPA 记为无穷大，CPA 退化为当前距离。

注意 CPA/TCPA 是在当前速度/航向保持不变假设下的线性预测。采取转向/减速后必须用更新后的运动状态重新计算，并同时用实际轨迹的最小分离距离验证。

## 9. CCS 标准映射与当前实现边界

| 标准相关点 | 工程中的对应实现 | 当前边界 |
|---|---|---|
| 5.2 输入/输出 | 本船/目标船状态、参数配置、路径偏置动作、可视化与 CSV | 暂无真实雷达/AIS/控制系统连接 |
| 7.1 态势判断 | 每个目标单独计算 CPA/TCPA、相对方位、简化会遇类别和三等级近似风险 | 风险分类没有完整复刻附录 A 所有临界点公式 |
| 7.3 局部路径规划 | 基线同时评分对全部目标的候选改向/减速动作；PPO 学习连续动作 | COLREGs 只是奖励与动作偏好的一部分，非正式认证规则引擎 |
| 7.3.2 / 附录 B SDA | SDA 可编辑；`ccs_reference.py` 包含附录 B.1（100m 散货船）示例中部分/全部列出的会遇距离值和 B.4 船型系数 | 附录 B 是资料性示例，100m 散货船数据不能直接映射成小型 USV 的法定阈值 |
| 8.2/8.3 多船测试 | 1V1、1V2、1V3；含附录 D.5 两目标初始参数和 D.6 中 TV1-TV3 的多船初始参数 | D.5/D.6 的目标船转向脚本未自动执行，默认按用户设定保向保速 |
| 7.5/7.7 显示与存储 | 轨迹、逐目标风险信息、CSV 运行记录 | 日志格式是研究原型，未声称满足 30 天 VDR 存储要求 |
| 6.1/7.4 设计运行范围/降级 | 可配置风浪流、可见距离、传感器误差；5 类故障注入与停推进请求；静态圆形障碍物和安全层 | 简化环境模型；未建模完整感知融合/报警回路/操纵失效恢复，不可当作完整故障安全机制 |

## 10. 建议下一步

1. 先确认 USV 的长度、最大航速、最大转向角速度、旋回圈/进距、减速和停船特性，再标定 SDA；小艇和标准附录中的大型散货船不可直接共用 SDA。
2. 加入标准附录 D 的目标船行动脚本、紧迫局面/行动不协调场景、目标船之间的冲突、静态障碍物和感知/控制延迟。
3. 用固定场景回归、随机场景蒙特卡洛测试、对抗性目标动作和消融实验评估 RL 策略；训练策略外面还需要安全屏蔽层或可验证的候选轨迹约束。
4. 在软件在环通过后，再规划硬件在环与受控水域测试；实船接入需要由有资质团队进行安全论证和测试。

## 13. GUI 原始测试用例读取与回放（v5）

打开 `run_gui.py` 或双击 `run_gui.bat` 后，右侧新增 **“测试用例回放”** 页：

1. 在分组列表选择“全部 / 1V1 / 1V2 / 1V3”。程序从项目内 `test_cases/` 直接枚举原始 CSV：1V1 138 个、1V2 99 个、1V3 31 个，总计 268 个。列表可滚动，选中后会显示原始会遇类型、阶段、本船初始航速/航向、各目标船航速/航向、初始距离/相对方位以及 CSV 中记录的 DCPA/TCPA。

3. 选择 **0.25x、0.5x、1x、2x、5x、10x、20x、50x 或“跟随计算速度（不限速）”** 控制连续播放。v7 改为每次动画回调只推进一个仿真步、更新一帧；加速只缩短帧间等待，不再一帧跨越多个仿真步。1x 每帧等待 180 ms，50x 约 4 ms。
4. 在 **“快进仿真秒数”** 中输入例如 `1800`，点击“快进（仍计算控制）”。程序将按当前仿真步长逐步执行船舶运动、规则/PPO 控制器、安全筛查并记录每一步日志，只略过中间逐帧绘图。因步长离散，实际快进时间取 `dt_s` 的整数倍；若提前触发碰撞或达到 GUI 的 1800 步硬上限，会少于请求时长，并显示实际推进的秒数。
5. 选择另一条用例后必须重新点击加载才能切换仿真；为避免对旧场景进行误操作，当前列表选择与已加载场景不同的时候，快进按钮会提示先加载。

建议流程：先选择用例 → 读取详情 → 加载/重新开始 → 输入希望跳过的秒数（例如 1800）→ 快进到接近阶段 → 选择 1x 或 2x 观察会遇与避让 → 用“单步运行”精细观察 CPA/TCPA 变化。快进不是把船直接移动到目标时刻；它会真实执行模型内的每一步，只省略中间动画帧。可从“停止 / 保存日志”关闭当前逐步日志。


### v6：计算极限回放（不限速）

v6 曾采用每 5 个仿真步绘制一次的批量刷新方式，底层每个仿真步仍完整计算并记入 CSV。

### v7：逐帧播放（加速/不限速均不主动跳帧）

v7 将播放调度改为 **每次回调只计算 1 个仿真步，并为该步刷新画面**。选择 2x、10x、50x 时，程序改变的是两帧之间的等待时间，不再一次批量推进多个步骤。因此可以连续观察目标船逼近、本船转向、航迹变化和分离过程。不限速模式通过 `after_idle` 调度下一帧，不插入人为定时等待，并在绘制完整帧后处理画布重绘。实际可见刷新速度仍受每步计算耗时、操作系统事件循环和显示器刷新率限制。

“快进仿真秒数”是有意省略中间显示帧的另一种操作：它仍然逐步运行控制器与动力学，但只绘制快进后的画面。需要观察避碰过程时，请使用连续播放而不是快进。

## 14. v8：本船回归计划航线后结束 + 时间线回看

### 结束条件

GUI 场景不再在目标船刚驶过或当前预测 CPA 安全时立即结束。系统先确认目标船已经物理通过（TCPA < -0.25 min 且当前距离大于 SDA）；对于距离足够远、相对速度近似为零的目标，也可作为不收敛的安全目标处理。接着进入“避碰后恢复计划航线”阶段，使用回归控制器朝计划航线前方点操纵。

本船必须连续 3 个仿真步同时满足以下条件，正常回合才会结束：

- 相对计划航线的横向偏差不超过 100 m；
- 航向与计划航向差不超过 4°；
- 航速与计划航速差不超过 1.5 kn。

发生碰撞或静态障碍物接触仍会立即终止并标为失败。GUI 硬上限是 1800 步（默认 5 秒/步，即 2.5 小时仿真时间）；系统失效导致无法返回时会明确报“达到仿真时限但本船未恢复计划航行”，不会将其算作安全通过。手动“停止 / 保存日志”按钮仍允许用户主动结束当前运行。

### 时间线进度条

船舶画布下方新增 **场景态势时间进度**。每一个仿真步都会存储本船/目标船的位置、航向、航速、传感器状态和累计安全统计。拖动进度条并松开鼠标，可查看该仿真时刻的船位、航迹、CPA/TCPA 和风险信息；时间标签显示当前/总仿真秒数与步数。

从历史时刻点击继续运行时，界面先逐帧播放已经记录的未来状态，回到时间线末端后再继续计算，不会因为回看而重复写入日志。需要开始一场新的独立仿真时，重新加载测试用例即可。快进仍是有意不显示中间动画帧的快捷操作，但每一步都会进入时间线，因此快进后的任意中间时刻仍可以拖动回看。
